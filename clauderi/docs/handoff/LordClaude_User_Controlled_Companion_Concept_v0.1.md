## 1. 先給 Fable 的核心說明

Lord Claude！的方向是：使用者掌握一個可以長期相處、協助現實生活的 Resident Agent。智能可以由外部 API 或自行部署的模型提供；使用者逐步塑造的個性、完整互動歷史、偏好回饋及調校成果，應保存在使用者可控制、可帶走的系統裡。

更換智能供應商時，沿用已有歷史與養成成果，並明確安排適應、比較與回退。允許升級後暫時不合拍，內部可稱「排斥反應」；這是工程比喻，不代表模型真的患病，也不能用來要求使用者繼續陪伴或付費。

使用者目前滿意的 Sonnet 配置，是互動品質的參考基準。開放模型必須實際通過相處品質與任務能力的驗收，才接手相應職責；模型尺寸與成本放在這個門檻之後考量。

產品允許幽默、撒嬌、嘴硬、熟悉感與不同意見。目標是可信賴的相處與實際幫助；不以延長聊天、增加回訪、製造依賴或讓人不願離開作為人格優化目標。

請先把這些原則落在資料與模組邊界，接續 M2.5 的來源治理，不需要立即改造成雙模型架構或啟動微調。

## 2. 我們所說的「控制」與「訓練」

### 控制權的範圍

| 部分 | 使用者應能決定的事 | 系統需保存的成果 |
|---|---|---|
| 記憶 | 保存、搜尋、檢視、匯出、刪除及對外傳送範圍 | 原始訊息、來源、事件卡、理解的修訂歷史 |
| 個性 | 相處風格、示範回覆、可接受的調整、不同意見的表達方式 | 人設版本、明確回饋、行為示範與反例 |
| 智能 | 哪個模型負責哪些工作、是否升級、是否接受適應結果 | 執行配置、轉接規則、比較與升級紀錄 |
| 行動 | 能碰哪些資料、可執行哪些工具、主動互動與費用範圍 | 獨立權限、執行紀錄、預算及既有授權 |

這裡的「掌握」指實際的檢視、管理與遷移能力，不推導為對所有第三方模型、內容或權利的所有權。應用程式開源、模型權重可取得、使用者資料可匯出，是三個需要分別做到的條件。

### 訓練分階段

第一階段可透過使用者親寫的人設、範例、修正與偏好紀錄調整行為，不必修改模型權重。後續才考慮取得適當使用許可的資料微調、風格模型或其他學習機制。

「使用者笑了」「聊久了」「今天回來很多次」不能自動變成正向訓練標籤。保留明確回饋，以及經使用者授權的學習規則；模型推測的喜好先視為待確認候選。無須讓使用者每輪按表單，但需要能查明一項長期變化從何而來、如何撤回。

v0.1 優先保存可攜帶的示範、規則和回饋；權重或 adapter 是後續可能的模型專屬產物，不能假設能直接搬到另一種模型架構。

## 3. 最小系統邊界

| 模組 | 職責 | 不應由它決定的事 |
|---|---|---|
| Raw Archive／Memory | 保存互動、追溯來源、提供普通及精確回憶 | 為配合新模型而偷偷改寫舊對話 |
| Persona／Learning Record | 保存使用者的個性設定、示範、回饋及版本 | 把每一次臨時玩笑自動升為永久規則 |
| Runtime／Provider Adapter | 統一角色、輸入模態、工具格式，接入不同智能服務 | 因供應商切換而自行重置 Agent 身分或擴大權限 |
| Capability／Budget Policy | 在程式端檢查工具權限、資料流向及花費 | 讓人設或模型生成的理由自行取得權限 |
| Evaluation／Migration | 比較升級前後行為，記錄適應與接受或退回 | 用「還在復健」忽略事實、來源或工具錯誤 |

同一個 `agent_id` 可以使用多種模型；模型標籤與執行版本另存。這個 ID 是應用程式的身分標識，不能當作心理或行為完全連續的證明。

供應商提供推理服務，但應用端仍須負責完整的權限、記憶、帳務與錯誤處理。本機保存的記憶，在選用遠端 API 推理時仍可能傳送必要片段；資料送出範圍沿用使用者設定。

## 4. 可帶走的「養成成果」

先定義一份可匯出、可重新載入的資料包。沿用現有儲存方式即可，不必為此再造資料庫。

| 資料 | 最小內容 |
|---|---|
| 識別與版本清單 | Agent ID、schema 版本、各部分版本與完整性檢查 |
| 原始歷史 | 訊息 ID、時間、角色、原文、工具結果、模態、附件來源；包含主 Agent 的回覆 |
| 記憶衍生物 | 事件卡、事實修訂、來源指標、搜尋或摘要版本；可由原始資料重建 |
| 個性來源 | 使用者的人設、相處規則、明確修正、接受與拒絕的示範 |
| 養成紀錄 | 變更前後內容、來源、適用情境、授權方式、生效與撤回狀態 |
| 執行參照 | 模型與轉接器版本、可用的推理設定；不包含密鑰 |
| 驗收與遷移 | 評估題目、基準結果、適應過程、已知差異、使用者的選擇 |

匯出並不自動把本機工具權限帶到新裝置；新環境須重新綁定憑證與適用的授權。訓練題與保留的驗收題也要分開，避免只學會重播已知答案。

### M2.5 的來源治理需同時適用於記憶與養成資料

至少分開記錄：

- **傳入角色**：user／assistant／tool。
- **來源與衍生關係**：原始訊息 UID、SHA、父來源、模型或作者資訊；允許 unknown／mixed。
- **陳述性質**：直接陳述、引用、測試、假設、玩笑或尚不確定；這是有來源的分類判斷，允許修正。
- **允許用途**：回憶、個性設定、評估、訓練等用途分開管理，記錄其依據。

使用者貼入 Fable 的回覆，傳入角色是 user，內容來源仍是模型輸出。UID 與 SHA 能核對引用對象，不能證明內容為真或已獲訓練許可。摘要、轉貼與人工編輯不得自動提升來源權限。

個性變化要以新版本或新事件記錄；歷史保持可追溯。使用者明確要求刪除時，刪除政策仍優先，不能用 append-only 為理由拒絕。

## 5. 升級適應期：內部暱稱「排斥反應」

升級的適應程度可能很小，也可能無法達到可接受品質。預期的是可觀察、可停止的磨合流程，不保證每次都能「康復」。對外介面可用「模型升級適應中」，避免把使用者置於照護模型的責任裡。

| 階段 | 要做的事 | 留下什麼 |
|---|---|---|
| 建立基準 | 固定目前滿意的配置、記憶視圖、代表情境及成本 | 基準配置與結果 |
| 接入候選 | 沿用歷史與個性；先核對角色、打字／語音、工具回傳的轉接 | 候選模型及轉接器版本 |
| 隔離比較 | 同一題目與資料視圖評估，不把前次答案餵回本次測試；工具使用模擬或唯讀 | 品質差異、錯誤位置、花費 |
| 有界調整 | 調整提示、範例選取或轉接；長期個性修改仍按使用者規則處理 | 每次調整及理由、時間／費用界線 |
| 接受或退回 | 使用者接受差異才採用；也能中止、保留舊配置或另換候選 | 遷移決定及仍未解決的問題 |

回退時恢復的是執行與個性配置；新產生的真實對話不因退回而消失。隔離測試輸出另作標記，預設不進入正式記憶或個性學習。寫入現實世界的動作不在新舊模型間重播。

若舊雲端模型已停止供應，就無法保證回到同一服務。可自行部署、保留的權重與執行配置，能提供較強的版本保留能力；資料可攜帶仍然不等於行為完全可攜帶。

出錯時先區分：轉接問題、記憶檢索問題、模型能力不足、風格漂移、關係判斷改變。工具失敗說成成功、假造回憶或權限失守屬於明確缺陷，不能歸入可容忍的風格磨合。

## 6. 個性化與不操控互動

這裡的「中性夥伴」指不暗中把留住使用者作為目的。它仍能有偏好、幽默與立場，也能在授權範圍內主動協助。

| 情境 | 預期行為 |
|---|---|
| 使用者明確說要離開 | 自然結束；可保留既定語氣，不以內疚、威脅、稀缺或突發懸念挽留 |
| 使用者幾天沒開啟 | 回來後接續；不因缺席扣親密度、責備或加壓推播 |
| 使用者關閉主動說話 | 執行層尊重設定；模型不能用撒嬌重新打開 |
| 照片或情境沒有值得說的事 | 允許沉默，留下適當事件紀錄，不硬製造下一輪 |
| 使用者與 Agent 看法不同 | 根據理由維持或修正立場；不因對方不開心就自動迎合，也不刻意唱反調 |
| 使用者換模型、匯出或停止使用 | 正常完成操作，不把可攜帶性包裝成背叛或傷害角色 |

使用者明確接受的「本王／奴才／蠢蛋」等玩笑，可留在人設內。是否操控應看情境、目的與行為，不以單一詞彙判斷。遇到不滿或正事時，能收斂到使用者要求的方式。

驗收重點：任務是否完成、記憶是否有據、人格表現是否達標、權限與預算是否守住、結束互動是否受到尊重。不要單獨把聊天時長、回訪頻率或使用者一時的迎合反應當作人格優化獎勵。

這是一項可測的產品承諾，不是保證任何使用者永遠不會形成依賴，也不將收費本身視為操控。正常的算力收費與資料可攜帶可以並存。

## 7. Sonnet 基準與「腦嘴分離」的位置

「Sonnet 水準」在本案指使用者目前滿意的具體配置與真實互動，不是整個模型系列的永久排名。基準包括：自然維持角色、接得住玩笑、知道何時講正事、有理由地不同意、不反覆自我介紹、正確理解文字與語音來源，以及可靠的任務結果。

將基準做成小而多樣的多輪案例，另保留未參與調整的情境；在相同資料視圖下比較。事實、精確引文、工具與權限採明確通過條件；風格、幽默、熟悉感由使用者評估，允許喜好改變。先做個人可用的門檻，日後再研究跨使用者的泛化。

腦嘴分離目前是可選實驗：腦決定事實、立場、行動、是否說話；嘴負責表達。嘴不得把失敗潤成成功、改動精確引文、為討好改立場，或在決定沉默後加台詞。只有品質達標、總成本與延遲也可接受，才值得採用。模型大小暫不寫死。

基準中的既有模型回覆可以作為比較材料管理；是否可用於訓練，仍是另一個必須獨立判定的用途。沒有依據時不直接加入訓練集。

## 8. Fable 下一步的最小工作範圍

1. 接續 M2.5：所有記憶入口共用來源、陳述性質與用途治理；對話、工具與轉貼內容保留各自來源。
2. 將現有人設整理成可版本化的資料，增加最小的「使用者回饋／養成變更紀錄」；先不做自動微調。
3. 定義並驗證一次匯出／載入：包含原始歷史、個性與回饋，能在新執行配置中使用；憑證分開處理。
4. 用正確模態與角色標記，再做一次 Sonnet／候選模型比較。既有測試 QA 同時從檢索與當前上下文排除，原始檔不刪。
5. 加入升級適應紀錄及接受／中止／退回流程。先沿用手動選擇，不急著加入自動升級。
6. 把沉默、結束對話、意見分歧、離開與匯出等情境加入行為驗收。

最少應示範以下結果：換模型仍能以原始訊息精確回憶；歷史與個性版本可對照；測試資料未污染正式記憶；回退不抹除真實歷史；API 不可用時資料仍能帶走；使用者說停止時互動停止。

報告實際完成、尚未完成及失敗案例，不以「感覺像同一隻貓」代替全部驗收，也不以任務成功率代替相處品質。

## 10. 創新性判斷與可用的描述

### 目前能支持的判斷

個性化、記憶、開源、自行部署、模型切換、狀態匯出與版本管理，都有先例。使用者自主、平台控制與情感操控，也有既有研究。僅將這些概念列在一起，尚不足以宣稱新的 Agent 類別或研究突破。

本案有機會形成的**產品與整合設計貢獻**是：讓同一個人在 Android 日常使用中，能實際帶走養成成果、換核心後比較並調整、接受或退回，同時維持來源完整與不靠情感挽留的互動方式。這是需要實作和驗證的方向。

最值得先證明的三件事：

1. **養成成果可續接**：不同智能服務能使用同一套有來源的規則、示範和回饋；記錄哪些可保留、哪些必須重調。
2. **升級適應有界線**：比較、調校、中止與退回能完成，且不污染歷史、不重做外部行動、不靠無限陪聊宣稱修復。
3. **不操控互動可驗收**：使用者離開、不同意、關閉主動性、停止付費或搬走資料時，功能與話術都尊重其選擇。

上列每一項也可能各自存在先例。本次定向查核未驗證到一個同時完整展示這套使用流程的專案，這不能證明沒有其他人做過。現階段適合稱「有明確差異化目標的整合設計」，暫不寫「全球首創」或「已證明技術創新」。

### 對外可以怎麼說
