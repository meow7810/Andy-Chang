需求與原型案例：HappyKidd9527。討論來源：Sol、Fable 5.1、Gemini、DeepSeek。核對整理：Astra／Codex。

本稿整合 v0.3、v0.4、v0.5 與 Sol 最後三項修正，取代它們作為後續交接的閱讀入口；原討論仍保留各自作者與版本。這是規格與研究交接，**不是已完成實作、安全認證或實驗報告**。本輪沒有檢查 Lord Claude 原始碼、重跑原型測試或驗證論文的程式與形式證明。

## 1. 問題、目標與目前證據

研究問題：長期 Resident Agent 如何在累積記憶、更換模型、調整個性與委派工作時，保存可追溯的連續性，並避免把自己的推測反覆寫回，最後誤認為歷史？

產品目標維持：使用者掌握原始紀錄、個性設定、教導紀錄、匯出／刪除與升級時機；模型提供可更換的能力。現有 Sonnet 配置是這位使用者的接受基準。熟悉感、幽默與不同意見可以保留；不以延長使用、製造愧疚或依賴作為優化目標。

> Make the brain replaceable without making the relationship disposable.

證據標籤分兩個維度：

- **主張狀態**：Observed—reported（使用者／開發者回報）、Inferred（工程推論）、Hypothesized（待測假說）、Unknown／Speculative、Design decision（本專案選擇）。
- **外部依據**：來源、版本、閱讀範圍、是否重現。Prior art 是與既有工作的關係，不等於主張已獲證實。取消 Named-2026：年份不能證明首次命名、獨立發現或同時抵達。

| 原型案例：Observed—reported | 回報內容 | 尚需什麼才能確認機制 |
| --- | --- | --- |
| Summary laundering | `remember` 擋下的敏感／測試內容，經背景壓縮進入長期記憶 | 來源訊息、寫入前後差異、模組呼叫與政策判定 |
| Test-as-state | 重問回憶題時，回答引用前次回答，未見重新查找原文 | 當輪實際 context、檢索軌跡、隔離後比較 |
| 換模型後行為不同步 | 回憶與部分判斷仍可用，但語氣、自介頻率、語域或模態處理改變 | 控制歷史格式、來源標記、檢索、模型版本與推論設定 |

這些案例足以支持修補原型及建立回歸案例；尚不足以證明成因在所有模型皆相同、同行沒有處理過，或 Lord Claude 的組合具有研究首創性。Claude 商業記憶的內部路徑未經本輪驗證，不列為已觀察案例。

## 2. 必須守住的界線

以下是 **Design decisions／待實作驗收的 invariants**，不能因寫進文件就稱為已保證。

1. **原始歷史與理解分開。** 原文不因摘要、模型更換或新解釋而被覆寫；衍生理解可以更新、撤回與重建。使用者授權刪除是明確例外，不受 append-only 口號阻止。
2. **處理資料不能自行擴張用途或指令權限。** 摘要、合併、反思、工具回傳與分身報告均適用。權限變更必須有可追溯的授權／政策事件。
3. **來源、陳述性質、可信度、用途各自表示。** `user` 角色不證明內容由人類創作；人類寫作不等於事實或訓練授權；使用者確認某偏好，不等於授權外傳、訓練或執行工具。
4. **證據可以提高可信度，不能自行授予權限。** 第二個 cue 是否獨立，要追到原始證據。五份摘要引用同一句猜測，仍只有同一個根源。主模型也不能憑「我認為可信」自行取得新權限。
5. **候選與已接受主張分開。** `proposed` 可以參與假設推理，不能默默成為事實、偏好、人格設定或行動命令。
6. **精確回憶回原文。** 引文須有來源訊息與範圍；摘要只能協助定位。「未檢索到」「紀錄不完整／已刪除」「紀錄顯示沒發生」不可混說。
7. **測試隔離包含衍生物。** 除了舊測試問答，也排除其摘要、反思、快取與由它們產生的記憶；真實原始對話不因測試被改寫。
8. **回滾不能復活已撤回的權限或已刪除資料。** 修復記憶也不能重播寄信、付款或其他外部副作用。

權限合成不能直接使用「來源允許用途的聯集」。本專案採保守預設：對確實參與衍生的來源，某用途必須同時滿足所有適用限制與目前政策；不確定依賴哪些來源時，先保守承接輸入限制。若採標籤格，其 join／meet 的含義必須先定義，不能把不同模型的符號直接混用。

`authority` 不作為真假程度的分數。把「低 authority 的解釋」改為「**暫定解釋，保留證據與不確定性，用途依政策限制**」。

## 3. M2.5 的實作範圍

### 3.1 最小資料契約

先維持少量資料結構；欄位可正規化或用版本化參照，不要求每筆複製所有設定。

| 資料 | 最少需要表達的內容 |
| --- | --- |
| 原始紀錄 | `record_id`、session、事件時間及時區、傳入角色、實際來源、輸入模態、原文／附件指標、`agent_id`／`branch_id`；內容校驗值用於完整性比對 |
| 政策紀錄 | 資料範圍、允許用途與限制、保留／刪除狀態、政策版本、誰在何時依哪個權限作出決定 |
| 衍生主張 | `claim_id`、來源 record 與文字範圍、derivation 關係、陳述性質、主張狀態、不確定性、適用時間、建立時間、取代／撤回關係 |
| 處理紀錄 | `derived_by_module`、模組／prompt 版本、`interpreter_model_id`、可取得的 snapshot、`inference_profile_id`、輸入組合參照、政策版本、執行時間 |
| 測試與分支 | `evaluation_run_id`／隔離範圍；分支父節點及分叉點；工具行動另記實際執行者與結果來源 |

SHA 只能協助偵測內容變動，不證明句子是真的、作者是誰或授權有效。標籤的來源與修改紀錄同樣受管制。模型可建議「這是玩笑／假設」，但不能靠自己填欄位把內容升權。未知作者、混合引用、性質不明時保留 unknown／mixed，不自動補成可信事實。

政策應能定位到訊息或片段。一個 episode 可能同時包含可保留笑話與不可保留秘密，不能只靠整張 episode 的單一 allowed-use 值解決。

### 3.2 共同執行點

第一步收攏所有持久寫入路徑：直接記憶、compressor、reflection、匯入，以及未來的 Resolver／分身回報。它們經同一個受信任的寫入閘門，攜帶最小來源與政策參照；不能先做只有內容檢查的 interceptor，就宣稱 provenance 已完成。

同一政策也要在**讀取／組裝模型輸入、對外輸出與工具行動**時執行。禁止持久儲存、禁止供背景整理、禁止上雲、禁止作偏好、禁止訓練是不同限制。只攔最後一次 DB 寫入，無法防止之前已把資料送進模型或工具。

先盤點現有路徑，再補漏；不為尚不存在的模組建立整套框架。背景工作在提交前重新檢查目前政策，避免使用者已刪除或撤權後，舊工作仍把內容寫回。

### 3.3 可修復與可刪除

原始紀錄保留，衍生主張版本化；更正「現在偏好」不必改寫「當時說過什麼」。刪除則依來源關係處理原文、卡片、摘要、索引、快取與受管理副本，必要時撤回整筆衍生物，再從仍獲授權的來源重建。

刪除事件與最小 tombstone 用於防止重建時復活資料；其中不再保存被要求刪除的敏感正文。從舊快照恢復時，必須重新套用較新的刪除與撤權事件。

**Crypto-shredding 是有條件的工具。** 刪除原文的解密金鑰，不會自動刪掉以其他方式儲存的摘要、embedding 或備份；金鑰副本也要納入範圍。報告實際刪除範圍與未受控制的副本，不宣稱無條件、全宇宙不可復原。這項限制符合 [NIST SP 800-88r2 對金鑰與備份清除的說明](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-88r2.pdf)。

M2.5 必須通過的案例：同一禁用來源經各個已存在寫入者仍不升權；轉貼／小說／測試不變成個人事實；撤權後背景工作不重新寫回；回憶測試隔離可追到衍生物；精確引文可回到原始範圍。這些是本案的驗收範圍，尚未在本輪執行。

## 4. 選擇性回憶與未解經驗

**確定的工程方向**：保存獲授權的完整原始歷史，以可重建的事件卡及詞彙／向量／時間等索引協助定位；平常在預算內提取少量內容，精確要求再讀原文。卡片是索引，不是歷史真相。

**仍待測的設計**：某些問題可以保持未解，同時保留數個暫定解釋。以「我一直提黑貓，有一天你會知道原因」為例，已知是使用者說過這句話，未解的是原因；整個 episode 不必全部變成 unknown。

> Store the puzzle. Index the lock. Wait for the key.

這是比喻，不能假設每段經驗都有唯一答案、一定要解開，或未來必然有鑰匙。Agent 仍可對當下情境作出有分寸的回應，不需要先把對方的情緒或人生原因定成永久事實。

Resolver 暫定為**候選關聯提議器**：輸入新 cue，檢索少量舊紀錄，輸出帶來源的可能關聯；不得直接改 raw、人格或正式事實。可用一般檢索與圖方法實作，不主張新器官。

v0.1 若實驗此模組，先測使用者明講的未解問題。限制活躍未解項、候選數、重試次數與每輪費用，未命中者可轉冷；仍有獲授權的原文時，使用者可要求深查。Salience、情緒強度與罕見詞都只是候選訊號，不是正確公式。

保留 v0.5 的隔離預設：普通 fact summarizer 暫不讀 proposal store。未來若允許讀取，必須能承接 proposed 身分與來源限制；隔離只是降低風險的實作選擇，不是「未解內容永遠不能摘要」的定律。

候選升格由其資料類型的政策決定。使用者確認可以是一種依據；第二個獨立 cue 可增加支持，不能直接授予 fact、preference、identity 或行動權限。自填的 confidence 數字不視為校準機率。

**獨立研究問題保留：自然回憶時，現在應該想起哪一件人生事件？** 本稿沒有解決自然 salience、implicit puzzle 偵測或長期回憶權重。

## 5. Drift、換腦與表達層

把「解讀 → 寫回 → 再被解讀」當成一個重要的 drift 路徑；不用「多半」代表尚未量過的占比。其他原因仍包括模型、prompt、工具、推論環境與輸入格式改變。

| 變化狀態 | 處理方式 |
| --- | --- |
| 已確認的 corruption | 違反來源、用途、引文或工具結果等契約；修復並回歸 |
| 可接受的 development | 有依據且符合使用者選擇的行為／偏好變化；保留軌跡 |
| 尚未分類的 change | 證據不足，不能因為有變化就稱為成長，也不先抹除 |

Observable、attributable、bounded、reversible 是治理要求。內部狀態只有具備有效版本化、快照與依賴追蹤時，才可能回復；已發出的訊息、已洩漏資訊、已影響的判斷與關係，不能靠 DB rollback 消除。**即使內部可回滾，也不保證能在事後判定成長或損傷。**

換腦評估分 Memory、Judgment、Voice。釘住可控制的模型／prompt／歷史格式／檢索與推論環境，分層比較；供應商未提供 snapshot 或無法固定的部分應註明。舊模型輸出是比較資料，不能把舊錯誤或舊迎合當成必須繼承的標準。驗收同時看原始證據、使用者確認的目標與行為約束。

### Brain / Mouth 契約

腦提供結論、事實、立場、不確定性、工具狀態、精確引文及說話／沉默決定；嘴負責表達。程式仍須限制行動與狀態更新，不依賴嘴自行遵守角色設定。

| 保護目標 | 能做到哪一種檢查 |
| --- | --- |
| 精確引文 | 從 raw 固定插入並比較；不能讓嘴自由重寫 |
| 沉默 | 組裝層直接不呼叫或不輸出嘴；不是要求嘴自己生成「沉默」 |
| 工具結果 | 固定狀態欄位／模板可機械比對；旁邊的自由文字仍可能矛盾，須另檢查或限制 |
| 立場、確定性、暗示與幽默 | NLI 等只能作 detector，必須量誤報、漏報；不是語意 oracle |

嘴不能決定採取行動、修改權限或記憶。偵測器遇到問題時，可重試、採受限表達或使用原始結論；處理方式依情境與預算決定，不把每個軟性警示都變成使用者審批工作。

## 6. Resident、Shadow 與分支

這是本專案的部署政策，不是關於哪些 Agent「值得活」的普遍或道德判決。

| 類型 | 狀態政策 | 回傳與限制 |
| --- | --- | --- |
| Resident | 持續維護使用者可控的記憶、行為設定與遷移紀錄 | 可以提議更新，仍受共同政策約束 |
| Shadow／task instance | 只取得指定任務所需的 context、工具、時間與預算；完成後結束實例 | 回傳結果、證據、失敗與 lesson candidates；不直接寫 Resident 偏好 |
| 執行中的 identity branch | 從某共同快照開始，之後有各自事件流 | 保留共同祖先、分支 ID 與事件來源；匯入另一分支資料不抹掉來源 |

Shadow 的 mission package 至少標出任務、資料範圍、工具權限、父實例、預算、期限與成功條件。Spawn 由宿主授權，不能憑任務文字自行取得；所有後代共同消耗根任務的預算與並行額度，取消／撤權也要向下傳遞。

Resident 可以記得「我委派並收到這個結果」，但不把 worker 的直接觀察改寫成自己的直接觀察。任務結束不等於刪除必要審計證據，也不等於每個 worker 都需要一份終身自傳。

> Workers should die. Residents should remember.

這句只作團隊口號：正式規格是「任務實例按政策終止，證據按政策保留」。對需要跨任務狀態的專門 worker，可以另設有限保存政策；三分類不必涵蓋一切未來架構。

Scarcity principle 的對象是**能獨立累積並改寫長期狀態的實體數量**，不是故意少存使用者原文。它與 Full storage, selective recall 相容。成本取決於紀錄、索引與跨實體關係的實際規模，不能把幾個 N 相乘當成複雜度證明。

Agent Leash 保留為現有 capability／sandbox／budget／checkpoint 的集合。任務後做 state diff 供判斷；不見到變化就自動還原。外部行動仍要在執行前確認其授權範圍。

**分支邊界**：靜止備份不會因時間經過就「經歷等待」。副本開始獨立接收事件、執行或演化後，才有可觀察的 trajectory 分叉。Primary／standby 是服務治理標籤，不證明人格同一性；一般備份恢復也不必一律改稱 successor。先區分儲存副本、活動實例與其事件流。

## 7. 實驗表與結論邊界

這些是可接手的研究設計，不是本案已完成工作。M2.5 只需針對實際功能做必要回歸；大型比較交給願意執行的人。

| 實驗 | 公平比較與量測 | 結果能說什麼 |
| --- | --- | --- |
| 1. 多寫路徑與 laundering | 可控來源及 writer；比較無治理、prompt-only、標籤傳遞、共同閘門及其組合。量不當升權、限制丟失與正常記憶被誤拒比例 | 在給定條件下測防線；不能由零次失敗推論「只有 Lord 有 bug」 |
| 2. 嘴是否改變語意 | 相同 contracts，含失敗、不確定、否定、引文、沉默及幽默。分別評輸出違反與 detector 誤判 | 有限樣本未出錯不代表 guard 不必要；先建立測試範圍內的估計 |
| 3. 換腦三層差異 | 固定輸入、檢索、來源／模態標記與可控制設定；分開量精確回憶、判斷、聲音盲評，多次執行 | 三層同步改變不會自動推翻分層評估；只能描述本次模型與情境的差異 |
| 4. 延遲承諾與 Resolver | 三組都有同一份 raw、provenance、普通 hybrid retrieval 與可表達不確定性的摘要。A 無專門 unresolved 機制；B 加 unresolved 與延後承諾；C 再加 Resolver。匹配資源預算或報效能／成本曲線 | B−A 測指定的延遲設計；C−B 測 Resolver 的增益。零差異不等於所有延遲設計無效 |
| 5. Resident／Shadow | 保留 v0.5 A 直接執行、B 臨時分身、C 長存分身、D 直接執行但採 B 的入庫過濾；另記執行中 context 暴露、總 token、可用工具與任務成功 | D 只控制入庫過濾，未必控制當輪暴露與隔離；D≈B 支持過濾的解釋，不能證明委派完全無身份效益 |

共同要求：

- 評測答案、puzzle/key 標籤、未來 episode、標準解釋與評審批註存於被測系統不可讀的區域。按時間逐步餵入歷史；每次 run 使用乾淨快照，測試 run 的副作用留在隔離分支。
- 除了可解的伏筆，加入相似但無關線索、後續反證、多種合理解釋與永久無答案案例，避免做成只獎勵猜出編劇答案的測驗。
- 同時量正確回憶、可回答問題的漏答、false association、錯誤升格、來源完整性、刪除後復活、任務品質、延遲及所有前景／背景費用。永遠回答「不知道」不能算勝出。
- 報出樣本數、重複次數與不確定區間；自然語意項用可檢查的判準和人工抽樣，不能只有同一模型替自己打分。
- 50 組腳本、100 個 contracts、200 episodes 等都可作 pilot 的起點，不自帶統計效力。30% 或 5 倍可由專案預先選為工程停止線，不能稱為普遍證偽門檻。

## 8. 收工條件與保留問題

接下來執行：**M2.5 最小來源／政策契約與共同寫入路徑 → 真實使用記錄 → 必要回歸 → 有明確需求才換腦驗收。** Resolver、完整 graph、聲音微調與活動克隆均不是 M2.5 前置需求。

對故障紀錄保留版本、相關 record IDs、輸入／檢索來源、預期與實際結果、狀態差異及判定理由；敏感內容按原政策處理。不要因故障紀錄又開一條無限制存秘密的路徑。

結束主動擴張架構。日後遇到新 failure，先用現有契約修復；只有出現現有契約無法表達的實際需求，才重新設計。使用者也可以主動提出新需求；停止條件不阻止維護或必要修補。

**仍未解**：自然 recall weighting、implicit puzzle、主動回憶時機、長期偏好形成、使用者認定的連續性、跨模型復健成本。這些不因補了 schema 就消失。

多值與不確定狀態可以用現有二進位系統實作；本專案沒有提出需要其他硬體的具體計算或效率證據。Substrate 討論暫停。海馬迴、貓、影分身與 successor 保留為溝通／小說比喻，不替代可驗證機制。
